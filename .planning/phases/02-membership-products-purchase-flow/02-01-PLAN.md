<objective>
Create the membership pricing page on poynt.no and the dedicated Stripe Checkout API route for subscription purchases.

Purpose: Users need to see available membership billing periods and complete a subscription purchase through Stripe Checkout. This is separate from the existing digital product cart/checkout flow because Stripe requires `mode=subscription` for recurring billing (incompatible with `mode=payment` used for one-time digital products).

Output: Membership pricing page at `/medlemskap`, a Stripe price creation utility for the 4 billing intervals, and a POST `/api/checkout/membership` endpoint that creates a Stripe Checkout Session in subscription mode.
</objective>

**1. Create `apps/web/src/lib/stripe/create-membership-prices.ts`:**

Define a pricing configuration constant and a utility function to create Stripe Prices for the membership product.

```typescript
export const MEMBERSHIP_PRICING = [
  { months: 1, amount: 99900, label: '1 maned', monthlyRate: 999 },
  { months: 3, amount: 269700, label: '3 maneder', monthlyRate: 899 },
  { months: 6, amount: 509400, label: '6 maneder', monthlyRate: 849 },
  { months: 12, amount: 959400, label: '12 maneder', monthlyRate: 799 },
] as const;
```

- Prices are in NOK ore (smallest unit). 99900 = 999 NOK.
- Each Price uses `recurring.interval = 'month'` with `recurring.interval_count` matching the months value.
- The `createMembershipPrices` function accepts a Stripe Product ID and creates all 4 Prices with metadata: `{ tier: 'community', billingPeriodMonths: string, billingPeriodLabel: string }`.
- Export the function and the pricing constant for use in the pricing page.
- This is a one-time setup script, NOT called on every request. It's meant to be run once to seed Stripe Prices. Include a note about this.

**2. Create `apps/web/app/api/checkout/membership/route.ts`:**

POST endpoint that creates a Stripe Checkout Session in subscription mode.

Request body: `{ priceId: string, tier: string }` where priceId is one of the 4 Stripe Price IDs and tier is 'community' or 'community_ai'.

Implementation:
- Import `getStripe` from `@poynt/stripe`.
- Validate that priceId and tier are present in request body.
- Optionally accept `email` in body for pre-filling; if not provided, Stripe collects it.
- Create checkout session with:
  - `mode: 'subscription'` (CRITICAL - not 'payment')
  - `line_items: [{ price: priceId, quantity: 1 }]`
  - `metadata: { productType: 'membership', tier: tier }` (used by webhook to route to membership handler)
  - `subscription_data: { metadata: { tier: tier } }` (attached to the Stripe Subscription object for lifecycle webhooks)
  - `success_url: ${NEXT_PUBLIC_URL}/medlemskap/bekreftelse?session_id={CHECKOUT_SESSION_ID}`
  - `cancel_url: ${NEXT_PUBLIC_URL}/medlemskap`
  - `customer_email: email` (if provided)
- Return `{ url: session.url }` as JSON.
- Wrap in try/catch, return 400 for validation errors, 500 for Stripe errors.
- Do NOT require Payload auth for this endpoint. Users may not have a Payload account yet (it's created in the webhook after purchase).

Pattern reference: Follow the same error handling style as the existing `/api/checkout/route.ts`, but use `mode: 'subscription'` instead of `mode: 'payment'`.
