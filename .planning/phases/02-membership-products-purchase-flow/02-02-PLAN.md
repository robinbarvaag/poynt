**1. Create `apps/web/src/lib/membership/sync-subscription.ts`:**

A reusable utility for syncing Stripe subscription state to both Payload and Drizzle databases.

Functions to implement:

**`getTierFromSubscription(subscription: Stripe.Subscription): MembershipTier`**
- Extract tier from subscription metadata first: `subscription.metadata?.tier`
- Fallback to price metadata: `subscription.items.data[0]?.price.metadata?.tier`
- Fallback to 'community' with console.warn if neither found
- Return validated MembershipTier ('community' or 'community_ai')

**`mapSubscriptionStatus(stripeStatus: string): MembershipStatus`**
- Map Stripe subscription statuses to Payload MembershipStatus:
  - 'active', 'trialing' -> 'active'
  - 'canceled' -> 'canceled'
  - 'past_due', 'unpaid' -> 'past_due'
  - 'incomplete', 'incomplete_expired', 'paused' -> 'inactive'
  - Default: 'inactive'

**`syncSubscriptionToPayload(params: { email: string, tier: MembershipTier, status: MembershipStatus, stripeCustomerId: string, stripeSubscriptionId: string })`**
- Find Payload user by email
- If found, update membershipTier, membershipStatus, stripeCustomerId, stripeSubscriptionId
- If not found, create Payload user (same pattern as existing handleMembershipPurchase in webhook):
  - Generate random password (Payload auth collection requires it, but user uses magic link/Google)
  - Set role: 'customer'
- Import `getPayload` from 'payload' and config from '@/payload.config'

**`syncSubscriptionToDrizzle(params: { email: string, tier: MembershipTier, status: MembershipStatus, stripeCustomerId: string, stripeSubscriptionId: string, currentPeriodStart: Date, currentPeriodEnd: Date, cancelAtPeriodEnd: boolean })`**
- Use canonicalizeEmail to find plannerUser by canonicalEmail
- If user exists, upsert into planner_subscription table (if it exists) OR simply log for now
- NOTE: The planner_subscription table may not exist yet. For Phase 2 v1, the primary sync target is Payload Users (source of truth per Phase 1 decision). Drizzle sync can be a console.log placeholder that logs the sync data. Add a `// TODO: Phase 6 - sync to planner_subscription table` comment.
- Import db, eq from '@poynt/planner-db' and plannerUser from '@poynt/planner-db/schema'
- Import canonicalizeEmail from '@/lib/email-normalize'

**2. Extend `apps/web/app/api/webhooks/stripe/route.ts`:**

Add new event type handlers to the existing webhook POST function. Keep the existing `checkout.session.completed` handler intact.

Add a switch statement (or extend existing if/else) for these events:
- `customer.subscription.created`: Call syncSubscriptionToPayload + syncSubscriptionToDrizzle. Send welcome email (import sendMemberWelcomeEmail from @poynt/email). Use `getTierFromSubscription` and `mapSubscriptionStatus`.
- `customer.subscription.updated`: Call syncSubscriptionToPayload + syncSubscriptionToDrizzle with latest status/tier. Handle upgrades, downgrades, cancellation scheduling (cancelAtPeriodEnd).
- `customer.subscription.deleted`: Set status to 'canceled' and tier to 'none'. Call sync functions.
- `invoice.paid`: Update subscription period dates. Re-sync status to 'active' (confirms renewal payment).
- `invoice.payment_failed`: Update status to 'past_due'. Call sync functions.

For each handler:
- Extract customer ID from event object (handle string vs Customer object)
- Retrieve customer email from Stripe: `const customer = await stripe.customers.retrieve(customerId); const email = (customer as Stripe.Customer).email;`
- Call sync functions with extracted data
- Wrap each handler in try/catch, log errors but still record event as processed

```typescript
export async function sendMemberWelcomeEmail(params: {
  email: string;
  memberName: string;
  tier: 'Community' | 'Community + AI';
}) {
  if (!process.env.RESEND_API_KEY) return;

  const { render } = await import('@react-email/render');
  const { default: WelcomeMemberEmail } = await import('./templates/welcome-member');

  const onboardingUrl = `${process.env.NEXT_PUBLIC_URL || 'http://localhost:3000'}/on-poynt/onboarding`;

  const emailHtml = await render(WelcomeMemberEmail({
    memberName: params.memberName,
    tier: params.tier,
    onboardingUrl,
  }));

  await getResend().emails.send({
    from: 'On Poynt <velkommen@resend.dev>', // TODO: Change to verified domain
    to: params.email,
    subject: 'Velkommen til On Poynt!',
    html: emailHtml,
  });
}
```

Keep the existing `sendWelcomeEmail` function for backward compatibility, but the webhook handler (Task 1) will use the new `sendMemberWelcomeEmail`.
