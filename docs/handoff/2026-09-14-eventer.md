## Beslutninger (med begrunnelse)

| Beslutning | Hvorfor |
|---|---|
| Egen collection for påmeldinger, ikke form-builder | Trenger status, kode, innsjekk, senere betaling/refusjon |
| Alt i Payload (`public`), ikke Drizzle | Påmeldte er ikke innlogget; alt administreres i Payload |
| API under `/api/eventer/…` | `/api/events/…` er Payloads REST-API for collectionen — kollisjon |
| `pg_advisory_xact_lock(7401, eventId)` i transaksjon | Hindrer overbooking også med flere Vercel-instanser (verifisert: 5 samtidige → 2+3) |
| E-post sendes etter commit, feil svelges | Treg Resend skal aldri holde låsen eller velte påmeldingen |
| QR inneholder billettlenken, ikke bare koden | Vanlig kamera åpner billettsiden; skanneren trekker ut token |
| Token med feltadgang `read: false` | Aldri ut via REST/admin; server leser med overrideAccess |
| Ingen billettlenke i API-svaret ved duplikat-e-post | Ellers kunne hvem som helst hente andres billett og melde dem av |
| Avmelding uten e-postbekreftelse | Hemmelig lenke er beviset; kvittering sendes etterpå |
| RichText + program + FAQ i stedet for sideblokker | Mindre å vedlikeholde (render, markdown, kvalitet) |
| `jsqr` + BarcodeDetector | iOS Safari mangler BarcodeDetector; jsqr trenger ingen worker (Turbopack-trygt) |
| Én kode per person, ingen «følge» | Robins valg; følge vurderes i fase 2 |
| «Påmeldingen åpen?» regnes ut i nettleseren | Eventsiden er statisk; `new Date()` i prerender er ikke lov med cacheComponents |

## Feller vi gikk i (og løsningen)

1. **`bunx tsc` fra rotmappa** hentet TypeScript 7 og skrev lockfile. Bruk `bun run typecheck` (turbo) eller
   `bun run --cwd apps/web typecheck`. Sjekket: bun.lock endret seg bare med QR-pakkene.
2. **PowerShell-cwd driver** mellom kall (`cd ../..` i ett kall påvirker neste). Bruk `bun run --cwd <pakke>`
   eller absolutte stier.
3. **FK `ON DELETE set null` på påkrevd kolonne** (`event_registrations.event_id NOT NULL`) — sletting av event
   ville feilet. Løst med `beforeDelete`-hook i `collections/events.ts` som sletter påmeldingene (migrasjonen urørt).
4. **`export const instant = false` fjernet IKKE advarselen** «uncached data during prerendering» på
   `/eventer/billett/[token]` (selv om kvittering bruker det). Løst med Suspense-wrapper (samme som
   `/forhandsvisning`). Bieffekt: ugyldig token gir HTTP 200 med «ikke funnet»-innhold, ikke 404 (siden er noindex).
5. **Dev-advarsel på `/eventer/[slug]`** («URL data … params outside Suspense») for slugs laget etter at
   serveren startet. Samme mønster som `tjenester/[slug]` — latt stå bevisst.
6. **Biome `useSemanticElements`**: `role="status"` → bruk `<output>` (husk `display: block`).
7. **Ikke POST til `/api/eventer/[id]/pamelding` mot dev-server med falske adresser** — `.env.local` har ekte
   `RESEND_API_KEY`, så e-post sendes. Test logikken direkte med `payload run` og `$env:RESEND_API_KEY=''`.
8. **`payload run` støtter `@/`-aliaset** i importerte lib-filer, men scriptet må ligge inne i `apps/web`
   (fra scratchpad feilet aliasene).
9. **`pg`-deprecation-advarsel** («client.query() when already executing») dukker opp under samtidige
   transaksjoner — kommer fra Payload internt, ikke vår kode.
10. **`seed-personvern.ts` overskriver /personvern** i databasen — ikke kjør uten å sjekke at ingen har
    redigert siden i admin.
11. **Resend innebygde bilder:** SDK-feltet heter `contentId` (camelCase) i resend@6.7; `cid:`-referanse i HTML.
    Forhåndsvisningen i admin bruker en SVG-plassholder fordi `cid:` ikke vises i iframe.
